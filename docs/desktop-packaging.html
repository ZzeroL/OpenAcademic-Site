    01这是一份设计稿

    桌面形态尚未实现。本页不是安装说明，而是边界文档：哪些能力必须保留、哪些可以舍弃、数据放在哪里、失败时怎么办。

    现状

    当前只有 Web 与 CLI 两种形态。桌面包没有发布，也没有承诺时间表。任何「已经支持桌面版」的说法都不准确。

    02目标形态

    目标不是把 Web 套一个壳，而是单用户、本地优先的研究工作站：

    • 复用同一套 core、工具与记忆，不另写一套 Agent。
    • 本地启动后端与前端，默认只监听回环地址。
    • 数据、论文与密钥都在本机，不依赖外部数据库。
    • 模型端点与 arXiv / OpenAlex 仍需网络；离线时只读已有数据。

    外壳选型（如 Tauri / Electron）尚未定稿。选型标准应优先看：安装体积、系统 WebView 依赖、进程管理与自动更新能力。

    03数据目录

    桌面版必须把数据放在用户目录，而不是安装目录：

    位置内容迁移
    UserDataSQLite、Chroma、论文文件、.secret_key可导出 / 导入
    Cache可重取的 PDF、模型响应缓存可清空
    Logs运行日志、崩溃转储可轮转

    桌面版与服务器共用 OPENACADEMIC_HOME 语义：切换目录就等于切换工作区。导入导出必须包含 .secret_key 的说明，否则用户换机后无法解密已存密钥。

    备份

    备份是一个目录复制动作，不是一个数据库导出命令。论文文件与向量索引都在目录里，只导出 SQLite 会丢依据。

    04运行期约束

    PROCESS

    单实例

    同一数据目录只允许一个实例运行；重复启动应聚焦已有窗口，而不是开第二个后端。

    NETWORK

    只监听回环

    默认 127.0.0.1，不开放局域网；需要远程访问时走显式配置，并提示风险。

    LIFECYCLE

    关窗不退任务

    关闭窗口应提示运行中任务；退出时保存 queued 状态，下次启动恢复。

    SECRETS

    系统钥匙串优先

    若可用，.secret_key 交由系统钥匙串保管；不可用时至少限制文件权限。

    这些约束的核心是：桌面版不是一个更小的服务器，而是一个数据归用户所有的本地工作区。

    05打包边界

    以下能力在桌面版里保留或舍弃，需要先定：

    能力桌面版理由
    Agent 内核 / 工具 / 记忆保留产品核心，不能分叉
    收件箱 / 清单 / 领域保留主界面
    多用户与管理员建号舍弃单用户本地，保留单账号即可
    systemd / Nginx舍弃改由外壳管理进程
    SSE 进度流保留本机回环，成本低
    自动更新待定需签名与回滚策略

    舍弃多用户不等于删除鉴权代码；桌面版可以用单账号模式启动，但数据模型仍保留 owner_id，避免未来迁移时重写。

    06未决问题

    • 外壳与 WebView：系统 WebView 版本差异会影响 SSE 与字体渲染。
    • Python 运行时：打包 Python 依赖还是要求用户自装；后者会显著提高上手成本。
    • 自动更新：签名、增量包、失败回滚、数据目录兼容都没有定。
    • 本地模型：是否支持本地推理端点；若支持，显存与进程管理需要额外设计。
    • 导入既有工作区：从服务器迁移到桌面，.secret_key 与论文文件如何校验。

    这些问题没有答案之前，不应发布「桌面版预览」。预览会制造支持承诺，而当前没有对应的验证能力。

    07验收标准

    1. 首次启动完成建工作区、建库、播种账号，且不需要命令行。
    2. 断网时能打开已有清单与条目，明确提示模型不可用。
    3. 关闭窗口后重开，queued 任务恢复，running 任务标为中断。
    4. 导出目录在另一台机器导入后，已存密钥可解密，判断出处可打开。
    5. 升级失败可回滚到上一版本，数据目录不被破坏。
    6. 崩溃后日志可定位到任务与工具步骤，而不是只有一段堆栈。

    这些标准与服务器部署的安全清单共享同一条原则：失败要可见，数据要可迁移。
