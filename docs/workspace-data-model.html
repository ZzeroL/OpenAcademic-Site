01建模原则：判断是主表

很多学术工具把论文当主表，判断是笔记的附属。OpenAcademic 反过来：判断是主表，论文是依据。一条判断可以引用多篇论文的多个节，但一条判断只有一个当前状态。

DOMAIN领域归属维度，不是文件夹。
→
ITEM判断主表；带状态与出处。
→
EVIDENCE依据论文 + 节锚点 + 引句。
→
TRAJECTORY轨迹append-only 变更日志。

这条原则决定了几件事：删除论文不能级联删除判断；判断的状态变更必须写轨迹；论文元数据可以刷新，判断的出处快照要保留。

领域会话里读写（save_note / save_item）到的论文会自动挂进当前领域（role=read，已有角色不动）；只读不写不挂，避免先读后拒的候选污染论文库。挂载失败只记日志，不回滚已落盘的笔记或条目。

02核心表

以下是逻辑表名与职责，物理表名、字段类型与索引以仓库迁移为准。

表职责关键字段（逻辑）写入方
domains领域与归属id、name、owner_id、status管理员 / 工作区
papers论文元数据与文件arxiv_id、doi、openalex_id、title、pdf_path、section_map扫描 / 工具
items判断主表id、domain_id、claim、status、paper_id、section、quote、quote_verified、locator_stateagent / 人
decisions本周决定id、week、text、status、evidence_item_idsagent 起草 / 人裁决
tasks派活与运行状态id、domain_id、prompt、status、created_by、last_step人 / runner
trajectory_events判断变更日志id、item_id、action、reason、actor、created_at只追加
channel_runs通道运行回执id、channel、domain_id、week、status、hits、error扫描
scan_candidates扫描候选池domain_id、week、identifier、state、dispatched_task_id扫描 / 派活
notes笔记与索引id、domain_id、body、embedding_ref、links人 / agent
出处快照

items 上的 section 与 quote 是判断发表时的快照，不随论文版本静默更新。论文换版后，应显式标记「出处需复核」，而不是自动覆盖。quote 与 quote_verified 是只加列的结果：老库启动时由迁移自动补列，旧条目照常可读。

03一条判断的字段

字段含义约束
claim判断本身，一句话不写过程，不写「本文认为」
status候选 / 确认 / 推翻 / 搁置只能经裁决或轨迹变更
paper_id主依据论文可空；空时显示「未定位」
section / quote节锚点与逐字引句发表时快照；不做自动补全
quote_verified引句是否已在对应节校验命中1 = 已核对；0 = 无引句或已失效
locator_state已定位 / 未定位 / 需复核未定位不可直接引用
domain_id归属领域不可为空；跨领域用多条目
owner_id起草者agent 或人，均可审计

字段设计里没有「置信度」。置信度不能替代人裁决，反而会让候选态看起来像已定稿。不确定性通过 locator_state 与候选状态表达。

引句也不是转述：发表时只接受与所报节逐字命中的连续片段；模型写不出合规引句时，宁可 located=false，也不允许编造。

04引句证据链：什么叫可引用

「有节锚点」只证明判断挂在哪一节，还不证明那句话在原文里。引句证据链把这一步收紧：located=true 的条目必须带一段逐字引句，发表与修改时都按归一化规则在所称节的解析正文里做连续子串匹配。

数据只加两列

列含义约束
quote逐句引句，发表时写入可为空：旧条目或 located=false
quote_verified是否在对应节里校验命中1 = 已核对；0 = 无引句或校验已失效

老库启动时由迁移自动补列，旧条目照常可读、引句为空；item_history 不加列——轨迹轴记的是判断的变更，引句是依据，不参与判断历史。

校验规则

  1. 归一化后匹配：Unicode NFKC、去零宽字符、弯引号归一、PDF 断行连字符与空白折叠、ASCII 大小写折叠。
  2. 长度 12–300 字符：太短证明不了论断（如「See Figure 2」），太长等于把整节贴进来。
  3. 必须在所报节：拿别的节或摘要冒充会被拒绝；abstract / 摘要 别名从产物的摘要字段校验。
  4. 只接受连续一段：含 … / ... 的多段拼接直接拒绝。

校验不过整条不写，返回 invalid_args 并附该节开头 200 字，模型可自行对齐后重发；通过才写 quote_verified=1。

修改与旧条目

  • 改引句：按生效后的 section 重新校验，通过才保留已核对状态。
  • 改节但没带引句：引句随旧节失效，自动清空。
  • 改判断：默认保留引句；quote_verified 只证明句子在原文里，不证明它支撑新判断。
  • 改为未定位：清空节与引句；旧条目显式标「无引句（旧条目）」，不隐藏。

证据等级在响应里派生、不落列：quote_verified=1 → verified_quote，anchor_located=1 → section_only，否则 unlocated。前端据此显示徽章，便于度量「可免核对比例」。

05归属字段与只读视图

界面不直接拼装表，而是读视图。当前有三类只读视图：

v_week_digest

本周清单

判断、粗筛未读、候选与通道异常汇总；按领域 + 周聚合。

v_domain_items

领域条目流

判断 + 出处 + 引句与核对态 + 当前状态；只包含未逻辑删除的条目。

v_channel_health

通道健康

每条通道最近一次运行状态、错误与下周是否重跑。

归属字段统一用 domain_id 与 owner_id。多用户隔离靠 owner_id 与领域成员关系，而不是在前端过滤。视图里不要出现跨用户聚合，除非显式标注为管理员视图。

06逻辑删除与迁移

  • 逻辑删除：deleted_at 非空即视为删除；视图过滤，轨迹轴不删除。
  • 论文删除：不级联删除判断；判断保留出处快照，标记「依据已移除」。
  • 状态回退：不直接改 status；写一条轨迹事件，再由事件派生当前状态。
  • 引句变更：v1 不写 item_history；清空引句只把 quote_verified 归 0，判断历史不受影响。
  • 迁移：只增不删字段；旧字段保留读兼容，写路径先切新字段。
迁移影响面

改 items 或 channel_runs 的字段时，至少检查：工作区视图、清单聚合、扫描去重键、轨迹轴回放、pytest 里的工作区模型测试。任何一项没有覆盖，就不要合。

07改动前的检查清单

  1. 新字段是否有明确的写入方与读取方？没有读取方的字段不加。
  2. 新状态是否需要在界面可见？如果需要，它落在哪个视图？
  3. 删除或合并是否破坏轨迹轴的可解释性？
  4. 是否改变了候选去重键？跨周已派候选会不会重新入库？
  5. 多用户隔离是否仍然成立？

这五条来自实际缺口：候选跨周重复、状态无落点、轨迹无法回放，都会让「可核对」失效。

08怎么扩展

扩展数据模型时，优先加事件而不是加状态字段。事件可以回放，状态字段只能覆盖。只有当查询性能确实需要时，才从事件派生冗余字段，并保证它可以重建。

能重建的，才允许冗余；不能重建的，必须保留原事件。
