收件箱、清单与领域：
三条主路由。

    01三条主路由

    路由回答的问题主要数据状态
    /inbox今天欠什么？状态线、三列看板、本周决定可用
    /digest这周判了什么、漏了什么？判断、粗筛未读、候选、通道异常可用
    /p/[projectId]/items这个领域现在知道什么？领域条目流、判断状态与出处已接后端
    /p/[projectId]/paper/[paperId]这篇原文里依据在哪？PDF 文档端点、节锚点、高亮路线图

    前三条路由共用一份工作区状态：在收件箱确认一条判断，切到领域条目流不需要重新拉取；在清单里派活，回到收件箱能立刻看到任务卡。路由是视图，不是数据边界。

    02/inbox：先给状态，再给输入

    收件箱的首屏不是输入框，而是状态线。它只说三件事：距组会几天、几条决定待确认、几条干完待验。扫一眼就知道今天欠什么。

    • 状态线：时间压力 + 待处理数量，不展示无关统计。
    • 派活框：一句话 + 领域选择，不做复杂表单。
    • 本周决定：agent 起草，人只裁决；推翻理由 agent 先起草。
    • 三列看板：派出的活 / 进行中 / 干完待验；进行中显示工具轨迹。
    • 清单摘要：判断、粗筛未读、候选、通道异常四个数，点开进 /digest。

    这五个区块的顺序是产品判断：先告诉你欠什么，再让你加活。很多工具反过来，先给输入框，再让人自己记住上下文。

    03/digest：覆盖情况比数量重要

    本周清单不是论文排行榜，而是覆盖报告。它至少包含四组数据：

    JUDGMENTS

    本周判断

    按领域分组，标出候选 / 确认 / 推翻 / 搁置；每条可回原文。

    UNREAD

    粗筛未读

    每篇附一句不读的理由，避免「没读」变成隐形状态。

    CANDIDATES

    扫描候选

    共多少、已派多少、未派多少；可一键派给 agent。

    CHANNELS

    通道异常

    哪条通道 skip / fail，原因与下周是否重跑。

    清单可以交付「不完整」的结果，但不能交付「不知道哪里不完整」的结果。这是页面与数据的共同责任。

    04/p/[projectId]/items：领域条目流

    领域是判断的归属维度，不是文件夹。条目流展示这个领域当前「知道什么」，每条判断带状态、出处与变更记录。

    FILTER按状态候选 / 确认 / 推翻 / 搁置。
    →
    READ按条目判断 + ID + 节锚点 + 引句。
    →
    TRACE按轨迹谁起草、谁确认、为什么改。
    →
    ACT裁决确认 / 推翻 / 搁置，理由必填。

    领域 IA 规划有 23 条路由，覆盖条目、笔记、论文、扫描、设置等；当前并非全部可用。新增路由前需要先确认它落在哪份共享状态上，避免出现「页面有自己的缓存」。

    05跳转规则

    跳转只读状态，不复制状态：

    • 收件箱 → 清单：携带当前周与领域筛选，不重置。
    • 清单 → 条目：点击判断直接定位到条目；返回时保留清单滚动位置。
    • 条目 → 原文：携带节锚点；阅读页未上线前，仅显示出处文本。
    • 候选 → 派活：只传候选清单，不预设阅读顺序；顺序由 agent 决定。
    不做的事

    不在 URL 里放敏感令牌；不通过前端拼装后端没有的统计；不用「小圆点」代替明确的通道状态。所有可见状态都必须有数据落点。

    06后端数据契约

    页面能承诺什么，取决于后端给了什么。几条核心契约：

    界面元素数据来源缺数据时
    状态线组会日期、待确认决定数、待验任务数显示「未知」，不猜 0
    三列看板tasks 状态 + 工具轨迹空列显示「暂无」，不伪造卡片
    本周清单判断、粗筛、候选、channel_runs缺通道回执时显式标「未运行」
    领域条目items + 出处 + 轨迹无出处显示「未定位」

    「缺数据时显示未知」比「显示 0」更重要。0 是一个事实，未知是另一个事实；把未知渲染成 0，会让漏检重新变得不可见。

    07阅读页的预留

    阅读页是当前最大的功能缺口。规划中的路由是 /p/[projectId]/paper/[paperId]，要同时满足三件事：

    • 原文：文档端点、节边界、页眉过滤，引句可高亮。
    • 分级：L1 速览 / L2 精读 / L3 复现，reading_level 可写。
    • 动作：高亮、批注、阅读进度；「精读才入库」的门槛。

    阅读页不是把 PDF 塞进 iframe。它要能把判断的节锚点映射到原文位置，否则「点开就是原文」仍然只是一句文案。完整缺口见已知限制与规划。
