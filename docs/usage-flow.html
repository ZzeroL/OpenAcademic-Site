一个人，一周，
从交活到组会。

    01周三：交一句话

    不选关键词、不挑论文、不配检索式。你只需要说清楚想弄明白什么，以及它属于哪个领域。

    inbox / compose
    ▸ 读 LooGLE 那篇，出节级笔记，重点看长依赖
领域 长上下文大语言模型
动作 派出去 → tasks: queued

    一句话派活的关键不是自然语言多漂亮，而是任务落库：刷新、断线、重启都不会丢。你交完就可以离开，不需要守着对话框。

    写一句话的建议

    写「要什么判断」比写「读哪几篇」更有用。读哪几篇、按什么顺序，归 agent 自己定；你只需要说清楚交付物长什么样。

    02周四到周日：它自己跑

    这段时间你不需要参与。系统按任务与周窗口做三件事：扫通道、读论文、写候选判断。

    SCAN三通道关键词 + 前向 / 后向引用，写回执。
    →
    PICK候选去重领域 + 周 + 标识；派过的跨周不再入库。
    →
    READ按节精读检索、下载、逐节读，工具轨迹可见。
    →
    WRITE候选判断save_item 落库，不直接定稿。
    →
    STOP待验干完的活停在收件箱，不自动采用。

    「干完待验」是流程的核心停顿点。它把模型的产出挡在人面前，而不是直接混进领域条目。没有这个停顿，后面的确认与轨迹就失去意义。

    03周一：收本周清单

    清单不是论文列表，而是本周判断 + 覆盖情况。打开时先看状态线：距组会几天、几条决定待确认、几条干完待验。

    digest / week示意
    本周判断12 条4 领域
    粗筛未读17 篇附理由
    扫描候选15 篇已派 6
    通道异常1 条429

    清单回答四个问题：这周判了什么、依据是什么、哪些没读、哪条通道没跑。它不追求把 17 篇未读读完，而是让你知道为什么没读。

    04组会：确认或推翻

    组会上讨论的不是「这个答案像不像」，而是「这条判断要不要采用」。每条候选都带着出处，讨论可以直接落到原文。

    CONFIRM

    确认采用

    判断进入领域条目，可用于稿子与综述；轨迹轴记录确认人与时间。

    OVERTURN

    推翻重跑

    理由必填；agent 先替你起草理由，你只改。推翻后原判断保留，不删除。

    组会不负责「让模型再多写一点」。需要补证时，正确动作是退回重跑或新建一个更窄的任务，而不是在对话框里继续追问——后者不会落到轨迹轴。

    本周决定 · 示意agent 起草 · 待确认

    本周不深读新论文，先把 3 篇种子补齐节级引句。

    依据 3 条已确认11-09
    确认 / 修改 / 推翻推翻时 理由必填

    05会后：勾四态

    组会结束后，给每篇相关论文勾一个阅读状态。四态不是评分，是下一步动作：

    状态含义下一步
    未读还没进入阅读队列留在候选池或粗筛
    粗筛L1 速览：看摘要、图表与结论决定是否进入精读
    精读L2：按节阅读，写判断与引句进入条目与组会讨论
    复现L3：复现实验或核对数值产出可引用证据

    勾四态的意义在于把「读没读」从口头承诺变成可见状态。粗筛未读要附一句不读的理由；精读才入库，避免把速览印象当成结论。

    现状

    阅读页与四态的可写 UI 仍在路线图中（见已知限制）。当前四态主要作为流程约定与数据字段存在，完整交互尚未落地。

    06人的四个动作

    01 · ASK

    交一句话

    说清要什么判断，不说怎么检索。

    02 · RULE

    确认或推翻

    对候选判断做裁决，理由入轨迹。

    03 · MEET

    开组会

    带着出处讨论，不靠记忆复述。

    04 · MARK

    勾四态

    把读没读变成可见状态。

    除此之外的动作——选关键词、挑论文、配检索式、追问模型、整理引用格式——都应该由系统承担或至少不成为主流程。人的时间应该花在判断上，而不是操作上。
