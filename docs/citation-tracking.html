01为什么走 OpenAlex

arXiv 预印本通常没有正式 DOI；即使有 10.48550，Crossref 也查不到对应记录。直接用 DOI 查引用链会大面积落空。

OpenAlex 以 work 为单位组织引用关系，能通过 arXiv id、DOI、标题等多个入口对齐。因此全文只从 arXiv 来，引用链与标识对齐走 OpenAlex，两套标识各司其职。

边界

OpenAlex 的引用列表可能滞后或不完整。后向引用只说明「它引了谁」，不保证穷尽；前向引用只说明「本周谁引了它」，不保证覆盖所有出版渠道。

02arXiv id → work：两条对齐路径

01DOI 直达用 arXiv id 找到对应 DOI，再查 OpenAlex work。
↓ 未命中
02标题兜底规范化标题 + 年份 + 作者约束，匹配唯一 work。
↓ 仍未命中
03显式未对齐标记并上清单，不猜、不静默丢弃。

标题兜底只在唯一匹配时采用。多个候选、标题差异过大或年份冲突，都按未对齐处理。对齐结果写入论文元数据，后续通道复用，避免每次重查。

结果条件后续行为
DOI 直达arXiv id 能映射到 DOI，OpenAlex 命中写入 openalex_id 与 doi
标题兜底规范化标题唯一匹配，年份一致写入 openalex_id，标记 matched_by=title
未对齐多候选 / 无候选 / 冲突标记 locator_state=unmatched，上清单

03前向：本周谁引了种子

前向引用回答「种子论文的新邻居」。每周对领域内的种子论文跑一次，只保留本周新增的引用关系。

  • 输入：种子论文的 OpenAlex work id。
  • 过滤：引用时间落在本周窗口；去重键用被引 work + 引用 work。
  • 输出：候选论文（引用者），来源标 forward。
  • 失败：429 / 超时记 skip 或 fail，清单可见。

前向引用的价值在于发现「刚开始引用种子的新工作」，而不是完整引用图谱。因此它不需要历史全量，只需要本周增量。

04后向：种子引了谁

后向引用回答「该读却没在读的邻近工作」。它对种子的参考文献列表跑一遍，把尚未入库的 work 变成候选。

  • 输入：种子的 OpenAlex referenced_works。
  • 过滤：排除库内已有论文、排除同周已派候选。
  • 输出：候选论文（被引者），来源标 backward。
  • 限制：OpenAlex 的引用列表可能缺项；缺失不补，按「未覆盖」处理。
示例状态

后向通道若遇 429，显示 skip 与「429 · 下次再跑」，而不是 0 命中。0 命中意味着跑过了但没有新候选；429 意味着没跑成。两者不能混。

05回执：ok / fail / skip

每条通道每次运行都写一条回执，至少包含：通道名、领域、周、状态、命中数、错误摘要、起止时间。

状态触发清单展示
ok正常返回，含 0 命中命中数 + 窗口
skip429、限流、主动跳过「下次再跑」+ 原因
fail超时、解析失败、数据源不可用错误摘要 + 是否重跑

回执不是日志，是产品数据。它决定清单里「通道异常」这一栏是否出现，也决定人下周要不要换源或补扫。

06对齐规则：对不上会标出来

  1. 优先稳定标识。DOI 直达优先于标题；标题只做兜底。
  2. 唯一匹配才采用。多候选不取最高分，直接判未对齐。
  3. 保留证据。记录用了哪条路径、匹配到的 work id 与标题差异。
  4. 不静默丢弃。未对齐的种子仍参与关键词通道，只是引用链跳过并标记。
  5. 可复核。对齐结果可以人工改，改动写回执，不覆盖原记录。

这套规则的目标不是把对齐率做高，而是让「对不上」可见。100/100 是当前代理样本的结果，不是永久保证。

07已知限制

  • OpenAlex 引用列表可能滞后，新预印本的被引关系不一定当周可见。
  • 标题兜底对同名论文、翻译标题、副标题变动敏感；宁可未对齐，不硬匹配。
  • 引用链只覆盖 OpenAlex 收录的 work，不覆盖未收录的会议论文或技术报告。
  • 后向引用不递归展开，避免候选爆炸；需要更深图谱时另开任务。
