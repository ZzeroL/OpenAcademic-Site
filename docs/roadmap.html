01一句话现状

从派活到回写，闭环已经能跑；1.1.0 把工作区与扫描接进主链，1.1.1 补上引句证据链与领域自动入库；从「人也能读」到「精确研究」，还差一层。

100%主链路可用
100%工作区已接后端
92%扫描与引用链双通道
24%阅读页未完成

百分比是粗略进度，不是精确工期。它的作用是让访客一眼看出：主链已经能用，阅读体验仍是最大缺口。

02已经落地

  • 收件箱 / 本周清单 / 领域条目流共用一份工作区状态，路由切换不丢操作。
  • 派活落库：tasks + 进程内队列，重启后 queued 自动恢复。
  • agent 发表判断：精读时经 save_item 写入领域，候选态由人确认或推翻；located=true 必须带逐字引句。
  • 引句证据链：发表 / 修改时按归一化规则在所称节正文里核对引句，quote_verified=1 才标「引句已核对」；徽章区分「引句已核对 / 仅节锚点 / 未定位」。
  • 领域自动入库：领域会话里 save_note / save_item 写到的论文自动挂进领域（role=read，已有角色不动）。
  • 工作区真值重取：进入主视图即重取工作区，会话续跑发表的判断不再等「确认采用」才出现在清单。
  • 已采用可回看：收件箱「已处理 → 已采用」的条目带执行现场链接，采用后仍能回到那次派活的会话。
  • 关键词通道：逐领域跑 arXiv，命中 / 失败 / 限流写 channel_runs。
  • 引用链通道：OpenAlex 前向「本周谁引了种子」与后向「种子引了谁」。
  • 扫描候选：落 scan_candidates，按领域 + 周 + 标识去重，可一键派活。
  • 三标识对齐：arXiv → OpenAlex 实测 100/100，引用链本期做。
  • pytest 覆盖：记忆层、领域容器、上下文回收、工作区模型、引句契约、通道与 PDF 读取。
可验证的说法

以上能力都能在后端数据里找到对应表或字段；界面只是这些状态的视图。判断一个功能是否真的落地，先看它有没有状态落点，而不是看页面上有没有按钮。

03四个最大的缺口

这些不是小修小补，决定「读」能不能从 Agent 的工具调用，变成人也能操作的阅读与批注。

01 · READING

阅读页与分级阅读

/p/[projectId]/paper/[paperId] 路由、L1 速览 / L2 精读 / L3 复现、reading_level 可写 UI、原文文档端点、高亮与批注、阅读进度、「精读才入库」门槛都还没有。

02 · LATEX

精确研究工具未注册

8 个基于 LaTeX 源码的精确工具（overview / outline / search / figures / tables / equations / references）写在代码里，但没注册进模型工具表，模型调不到。

03 · WORKSPACE

导入与笔记操作

本地 PDF 导入没有 multipart 端点；领域笔记页只读，没有新建、编辑与反链；跨领域笔记列表与向量召回也还没有。

04 · FRONTEND

搜索、编辑与长会话

会话历史没有全文搜索；笔记没有编辑能力；connect 回放没有分页；长会话的消息导航没有虚拟化。

04部署前必改

内部小团队可以先跑；对公网开放前，至少把这四组事情处理掉。

事项现状要求
默认管理员口令admin@example.com / admin123 写在源码里首次登录立即改密
账号开通没有注册入口管理员建号
.secret_key解密已存 API Key 的唯一钥匙备份，不要重新生成
依赖与发布门禁部分检查未强制lock 文件 / lint / typecheck
公网前还要补的安全项

Cookie 尚未设 Secure；会话令牌按明文存储；配置密文是 AES-CBC 无 MAC。应补 HTTPS、令牌哈希与 AES-GCM / HMAC。CORS 目前全开，登录也没有失败节流。

完整步骤见服务器部署与升级。CI 在 GitHub Actions，主仓在 Gitee；需要镜像或自建 runner。

05验证债

有些代码写完了，还没在真实环境里跑过。这些只能人工跑，按组一次跑完最省事。

  • 多用户隔离
  • PDF 真样本页眉过滤
  • 领域 IA 23 条路由
  • 前端 IA：登录 → 交活 → 四态回写
  • 上下文回收 B1–B8
  • 一次真机精读端到端
  • 引句校验与 PATCH 矩阵
  • LaTeX 产物与节边界一致性
优先补测

crypto_utils 往返与 mask、load_model_config 合并优先级、AgentState.update_todos 的五种终止路径、run_agent_stream 的事件序列、多会话并发写入与断连续跑。

Agent 主循环、限流、笔记与后端路由目前没有自动化测试。验证债不是「质量不好」，是「还没有证据说它好」——在产品里，这两者的区别很重要。

06刻意不做

提 PR 前先对齐：有些东西不是没做，是决定不做。

  • 每人自带 API Key（BYOK）
  • 登录改 JWT
  • 对话里直接建领域
  • 删除论文的 UI 入口
  • run_bash 进模型工具表
  • 统计持久化与历史回溯
  • 会议纪要 / PPT / 外部日历
  • 无界 todo 硬拒

判断标准见产品主旨：是否强化「判断—出处—轨迹」主链。

07接下来往哪走

方向不是「更聪明的模型」，而是模型越强越值钱的资产：证据链、轨迹轴、通道运行记录。

方向落点为什么现在做
可追溯综述paper_id + section + quote单条引句已落地，差聚合与排版
评估citation precision / hallucination rate没有指标就无法证明「可核对」
多源检索与图谱Semantic Scholar / PubMed / 引文图谱单 arXiv 覆盖不了邻近工作
RAG可配置嵌入 / rerank / 来源标注笔记检索已有索引，缺可调参数
产出LaTeX / BibTeX / Word / PDF判断要进稿子，不能只停在界面
目标不是完美召回，是让漏检可归因。
